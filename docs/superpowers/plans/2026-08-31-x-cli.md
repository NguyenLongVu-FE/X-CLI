# x-cli implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a macOS-first CLI and reusable agent skill for safe, user-approved reading and writing through the official X API.

**Architecture:** A dependency-light TypeScript package separates OAuth and Keychain storage, HTTP transport, read operations, immutable write previews, and single-action execution. The CLI emits JSON or NDJSON on stdout, diagnostics on stderr, and never sends a write until an approved action ID is executed.

**Tech Stack:** Node.js 22, TypeScript 5.8, Zod 4, Vitest 3, native `fetch`, native HTTP loopback server, macOS `security` command, pnpm.

**Spec:** `docs/superpowers/specs/2026-08-31-x-cli-design.md`

## Global constraints

- Use only official X API v2 endpoints. Do not automate or scrape the X website.
- Support macOS ARM64 and Node.js 22 first.
- Store OAuth tokens in macOS Keychain, never in repository files or logs.
- A write command creates one expiring preview. Only `x action execute <id>` performs that exact action.
- No global confirmation bypass, batch engagement, direct messages, or background automation.
- Keep stdout machine-readable and send diagnostics to stderr.
- Do not blindly retry writes after an ambiguous response.
- Use the package name `@nguyenlongvu-fe/x-cli`; the unscoped `x-cli` name is already occupied.
